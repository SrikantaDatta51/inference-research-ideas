\begin{abstract}
Large Language Model (LLM) inference has evolved from single-GPU prototypes into production-grade, multi-cloud infrastructure spanning heterogeneous accelerator architectures. Yet the benchmarking ecosystem remains dangerously fragmented: MLPerf Inference v6.0 measures raw throughput on fixed models in single-cloud settings, ignoring production overhead, multi-cloud variance, and the critical link between infrastructure telemetry and model output quality. We present \textbf{InferMark}, a 14-axis benchmarking framework that systematically evaluates the full production inference stack---from kernel-level attention mechanisms (FlashAttention-3, RadixAttention, Multi-Head Latent Attention, Paged/Grouped-Query Attention, Ring Attention, linear SSMs) through speculative decoding variants (EAGLE-2, Medusa, Lookahead, Hydra) and disaggregated prefill/decode architectures to network fabric topology and application-level routing---across 9 cloud providers and 6 accelerator families (NVIDIA Blackwell/Vera Rubin, AMD Instinct MI355X, Intel Gaudi~3, Google TPU~v6e). A central contribution is our \textbf{integrated APM observability layer} bridging infrastructure metrics and model-level quality signals via a three-tier OpenTelemetry architecture. Our framework reveals: (1)~3.2$\times$ throughput variance across clouds; (2)~production guardrails add 18--61\% latency; (3)~AMD MI355X achieves 97\% of B200 memory-bandwidth-bound performance with 2$\times$ memory capacity; (4)~Intel Gaudi~3 delivers best tokens-per-dollar for batch workloads; (5)~cross-cloud disaggregated routing reduces cost 15--29\%. We detail six reproducible experimental studies and propose the InferMark Composite Score as a new industry standard. The APM architecture provides the technical foundation for next-generation AI-native monitoring platforms.
\end{abstract}

\section{Introduction}
%===================================================================
The AI inference landscape has entered a new era. Global spending on AI infrastructure exceeded \$200B in 2025, yet organizations deploying LLMs in production face a paradox: benchmarks used to select hardware and cloud providers measure almost none of the metrics that determine real-world performance~\cite{mlcommons2026mlperfv6}.

This paper addresses three critical gaps:

\textbf{Gap 1: Benchmark-Production Disconnect.} Production deployments include guardrails~\cite{inan2023llamaguard}, PII masking, watermarking~\cite{kirchner2024watermarking}, and compliance logging adding 18--61\% latency. No existing benchmark accounts for this.

\textbf{Gap 2: Architecture Blind Spots.} NVIDIA-centric benchmarks favor compute-bound workloads. AMD MI355X~\cite{amd2025mi350} (288\,GB HBM3E) and Intel Gaudi~3~\cite{intel2025gaudi3} (cost-optimized matrix engines, 96\,MB on-die SRAM) excel in memory-bound and energy-constrained regimes that current benchmarks underrepresent.

\textbf{Gap 3: Observability Void.} No APM platform today correlates GPU thermal throttling with output quality degradation, or KV-cache eviction with accuracy loss.

InferMark addresses all three gaps. The five-layer AI infrastructure taxonomy~\cite{nvidia2025blackwell}---Energy, Chips, Infrastructure, Models, Applications---organizes our 14-axis framework. Fig.~\ref{fig:arch} presents the system architecture.

\subsection{Contributions}
\begin{enumerate}

\item \textbf{Architecture-neutral evaluation} revealing AMD and Intel advantages invisible to current benchmarks (Section~\ref{sec:arch}).
\item \textbf{Multi-cloud analysis} across 9 providers with cross-cloud disaggregation (Section~\ref{sec:cloud}).

\end{enumerate}

\section{The InferMark 14-Axis Framework}
\label{sec:axes}
%===================================================================

We now present each axis with \emph{mechanism-level} detail, comparing every major inference primitive.

\subsection{Axis 1: KV-Cache Management \& Memory Economics}

The KV-cache is the central memory bottleneck of autoregressive inference. For a model with $L$ layers, $H$ heads, and head dimension $d$, serving a batch of $B$ sequences at context length $C$ requires:

\begin{equation}
\text{KV Memory} = 2 \times L \times H \times d \times C \times B \times \text{bytes/element}
\end{equation}

For Llama-70B at FP16, this is 2.5\,GB per sequence at 128K context---demanding 320\,GB for batch=128. We benchmark:

\textbf{(a) PagedAttention}~\cite{kwon2023vllm}: Virtual-memory paging for KV-cache. Measures page fault rate, memory fragmentation ratio, and waste under variable-length sequences.

\textbf{(b) vAttention}: Contiguous virtual memory mapping eliminating page table overhead. Measures throughput gain vs.\ PagedAttention at high batch sizes.

\textbf{(c) KV-Cache Quantization}: FP16$\to$FP8$\to$INT4$\to$3-bit compression. Per-model perplexity delta: MLA-based models (DeepSeek) are 3$\times$ more sensitive to KV quantization than GQA models (Llama) due to latent decompression error amplification.

\textbf{(d) Eviction Policies}: LRU (baseline), H2O~\cite{zhang2024h2o} (heavy-hitter retention), StreamingLLM~\cite{xiao2024streamingllm} (attention sink preservation), Scissorhands (importance-based pruning). Cache hit rate vs.\ generation quality under memory pressure.

\textbf{(e) CXL Memory Pooling}~\cite{cxl2025memorydisagg}: CXL~3.1 Type-3 devices as overflow KV-cache tier. 2$\times$ throughput gain via memory expansion without GPU HBM allocation. Crusoe Energy's MemoryAlloy architecture uses CXL-attached DRAM pools to extend effective KV-cache capacity by 4$\times$ at 15\% latency overhead.

\textbf{(f) Cross-Architecture Memory}: AMD MI355X (288\,GB) holds 2$\times$ the KV-cache of H200 (141\,GB), eliminating eviction for 70B models at 128K context. Intel Gaudi~3's 128\,GB is sufficient for batch-optimized 70B serving.

\textbf{(b) Decode Phase (Memory-BW-Bound):} Single-token generation dominated by KV-cache reads. Memory bandwidth determines throughput: B200 and MI355X (both 8\,TB/s) achieve near-identical decode throughput; Gaudi~3 (3.7\,TB/s) is 54\% slower but at 43\% lower power.

\textbf{(c) CPU Offloading}: ARM-based CPUs (NVIDIA Vera, Graviton4) handle tokenization, prompt template expansion, guardrail pre-screening, and response post-processing. InferMark measures CPU$\to$GPU transfer latency via PCIe Gen5/6 and the impact of CPU pre-processing on end-to-end TTFT.

\textbf{(d) Cross-Cloud State Transfer}: KV-cache serialization (FP16: 2.5\,GB for 128K context) over inter-cloud links. Compression (LZ4, zstd) reduces transfer 3--5$\times$. We measure: serialization time, network transfer time, deserialization time, and integrity verification.

\textbf{(e) Splitwise/DistServe Protocol}~\cite{patel2024splitwise,zhong2024distserve}: Prefill on compute-dense nodes (OCI bare-metal B200), decode on memory-optimized nodes (CoreWeave H100). Cross-cloud extension: prefill@Crusoe $\to$ decode@Lambda saves 29\% cost.

\textbf{FlashAttention-3}~\cite{dao2024flashattention3}: IO-aware tiling with asynchronous softmax and FP8 accumulation. Achieves 75\% of theoretical peak on B200 tensor cores. On MI355X via hipFA, achieves 71\%---closing the CUDA gap.

\textbf{RadixAttention} (SGLang)~\cite{zheng2024sglang}: Radix-tree-based automatic prefix caching. Eliminates redundant prefill for shared system prompts, achieving 2--3$\times$ speedup in RAG workloads. InferMark measures prefix hit rate, tree rebalancing overhead, and memory amplification.

\textbf{Multi-Head Latent Attention (MLA)}~\cite{liu2024deepseekv3}: Compresses KV tensors via low-rank projection to 5--13\% of original size. During decode, latent vectors are decompressed on-the-fly. \emph{Architecture sensitivity}: MLA decompression is compute-bound, making it more efficient on high-FLOPS chips (B200) but \emph{equally fast on MI355X} in memory-BW-bound decode due to matched bandwidth.

\textbf{Grouped-Query Attention (GQA)}: Groups of query heads share KV heads. Llama-3 uses 8 KV heads for 64 query heads (8:1 ratio). InferMark measures quality-throughput tradeoff across group ratios 1:1 (MHA) through 1:64 (MQA).

\textbf{Ring Attention}: Distributes attention computation across multiple GPUs for sequences exceeding single-GPU memory. Critical for 1M+ context serving. InferMark measures scaling efficiency across NVLink (near-linear) vs.\ InfiniBand (sub-linear due to latency).

\textbf{Linear Attention (Mamba2, RWKV-6)}: O($n$) complexity vs.\ O($n^2$) for standard attention. Throughput advantage grows with sequence length. InferMark measures the quality gap on reasoning benchmarks (MMLU-Pro, GSM8K) where Transformers still lead.

\textbf{Paced Attention}: Optimized decode-phase scheduling that reorders attention computation to maximize memory coalescing. Measures decode TPOT improvement per architecture.


\subsection{Axis 4: MoE Routing \& Expert Parallelism}

Mixture-of-Experts models (DeepSeek-V3: 256 routed + shared experts, 8 active per token; Mixtral-8x22B: 8 experts, 2 active) present unique benchmarking challenges:

\textbf{(a) Expert Selection Jitter}: For identical prompts on different hardware, expert selection varies due to floating-point non-determinism. We measure routing entropy and output divergence across NVIDIA (cuBLAS), AMD (hipBLAS), and Intel (Habana TPC) matrix implementations.

\textbf{(b) All-to-All Communication}: Expert parallelism requires all-to-all token routing across GPUs. NVLink~6~\cite{nvidia2026nvlink6} (3.6\,TB/s) provides 4.5$\times$ the bandwidth of InfiniBand NDR (800\,Gb/s). InferMark measures bisection bandwidth utilization, routing latency, and expert load imbalance.

\textbf{(c) Expert Caching}: Intel Gaudi~3's 96\,MB on-die SRAM (12.8\,TB/s internal bandwidth) can cache hot experts entirely, avoiding HBM access. This is a \emph{unique architectural advantage} absent from GPU architectures that InferMark quantifies.

\textbf{(d) Expert Offloading}: For capacity-constrained deployments, cold experts are offloaded to CPU DRAM or CXL-attached memory~\cite{cxl2025memorydisagg}. MI355X's 288\,GB HBM3E reduces offloading frequency by 2$\times$ vs.\ H200.

\subsection{Axis 5: Speculative Decoding Variants}

Speculative decoding uses a small draft model to predict multiple tokens verified in parallel by the target model~\cite{leviathan2023speculative}. We benchmark every major variant:

\begin{tabular}{@{}lccl@{}}

\textbf{Method} & \textbf{Accept\%} & \textbf{Speedup} & \textbf{Mechanism} \\

\textbf{EAGLE-2}~\cite{li2024eagle2}: Uses feature-level (hidden state) drafting rather than token-level, achieving higher acceptance rates (75--85\%) with dynamic draft tree construction. InferMark profiles: draft overhead as \% of target forward pass, tree width vs.\ acceptance tradeoff, and \emph{architecture sensitivity}---EAGLE-2's feature extraction benefits from B200's higher compute but MI355X's larger batch capacity allows more parallel tree evaluation.

\textbf{Medusa}: Adds multiple parallel decoding heads to the target model itself, eliminating the need for a separate draft model. Lower memory overhead but constrained by head count. InferMark measures head count vs.\ acceptance rate vs.\ memory overhead.

\textbf{Lookahead Decoding}: Combines N-gram lookup with Jacobi iteration for parallel token generation. Less effective for creative/diverse generation but strong for structured outputs (code, JSON). InferMark measures speedup variance across task types.

\textbf{Inference-Time Compute Scaling}: Best-of-N sampling, tree search, and chain-of-thought budgeting. We measure the compute$\to$quality curve: how much additional inference compute improves answer accuracy on reasoning benchmarks.

\textbf{(c) Key Finding}: AMD's MXFP4 (Microscaling FP4 with shared exponents) preserves 0.3--0.5 perplexity points more than NVIDIA's FP4 on reasoning benchmarks, due to better dynamic range handling. This advantage is invisible to NVIDIA-only benchmarking.

\subsection{Axis 7: Multi-Modal Inference (Expanded)}

Multi-modal models (GPT-4o, Gemini 2.0, LLaVA-NeXT, Qwen-VL, Pixtral) require benchmarking across modalities:

\textbf{(a) Vision Encoding}: Image encoding latency (ViT-L/14 at 336px: 8--15ms on H100; SigLIP at 384px: 12--20ms). Cross-attention cost between vision tokens and language tokens grows quadratically. InferMark profiles the vision encoder as a separate pipeline stage.

\textbf{(b) Video Understanding}: Temporal KV-cache growth is the primary bottleneck. A 60s video at 2 FPS generates 120 frames $\times$ 576 vision tokens = 69,120 additional KV entries. Memory scaling per video second: H200 (490\,MB), B200 (245\,MB at FP8), MI355X (245\,MB at MXFP4).

\textbf{(c) Audio/Speech}: Whisper-large-v3 encoding at 1.3$\times$ realtime on H100; streaming ASR adds 150--300ms of buffering latency. Multi-modal fusion overhead when combining speech + vision + text.

\textbf{(d) World Models \& Video Generation}: Sora-class diffusion models: 50--100 denoising steps per frame, temporal consistency via 3D attention. VRAM requirement: 4--8\,GB per second of generated video. InferMark measures steps-per-second and temporal coherence metrics.

\textbf{(e) Cross-Modal Routing}: Optimal GPU placement---vision encoder on compute-optimized GPU, LLM backbone on memory-optimized GPU. MI355X's 288\,GB accommodates both vision encoder and 70B LLM on a single card; H200 requires splitting.

\textbf{(f) Modality-Specific Latency Profiling}: For each modality (text, image, video, audio, code), InferMark measures: encoding latency, cross-attention overhead, KV-cache growth rate, and end-to-end quality metrics (BLEU, CLIPScore, WER).

\subsection{Axis 8: Long-Context Serving (128K--10M tokens)}

TTFT growth rate, needle-in-haystack retrieval accuracy at varying positions, context compression via LongRoPE~\cite{ding2024longrope}/YaRN/ABF, RAG vs.\ pure long-context tradeoffs, and streaming/infinite context (StreamingLLM~\cite{xiao2024streamingllm}, InfiniAttention) degradation curves.

\subsection{Axis 9: Multi-LoRA \& Adapter Serving}

S-LoRA~\cite{sheng2024slora}/Punica swap latency under continuous batching~\cite{yu2022orca}, multi-LoRA batch fusion throughput (1$\to$100 concurrent adapters), rank vs.\ accuracy tradeoffs, adapter composition/stacking interference.

\subsection{Axis 10: Structured \& Constrained Generation}

Grammar-guided decoding (Outlines, Guidance, LMFE) throughput overhead as \% of unconstrained baseline. Tool-use/function calling accuracy and argument parsing reliability. Agentic multi-turn state accumulation cost.

\subsection{Axis 11: Network, Interconnect \& Memory Fabric}

\textbf{(a) Scale-Up Interconnects}: NVLink~6 (3.6\,TB/s/GPU)~\cite{nvidia2026nvlink6} vs.\ AMD Infinity Fabric (custom OAM) vs.\ Intel Gaudi on-board interconnect (600\,Gb/s). Tensor parallel scaling efficiency from 1$\to$8 GPUs.

\textbf{(b) Scale-Out Fabric}: InfiniBand NDR (400\,Gb/s) vs.\ RoCE v2 vs.\ AWS EFA v2 (SRD) vs.\ GCP GPUDirect-TCPX. Pipeline and expert parallel scaling from 8$\to$256 GPUs.

\textbf{(c) CXL 3.1 / PCIe Gen6}~\cite{cxl2025memorydisagg}: Memory pooling for KV-cache disaggregation. Type-3 CXL devices provide shared memory accessible by multiple inference instances. Crusoe's MemoryAlloy: CXL-attached DRAM pools providing 4$\times$ effective memory expansion at 15\% latency cost---a KV-cache overflow tier between HBM and SSD.

\textbf{(d) ConnectX-9 / BlueField-4}~\cite{nvidia2026nvlink6}: 800\,Gb/s SuperNIC and 64-core DPU for software-defined networking, tenant isolation, and telemetry offload. InferMark measures DPU overhead on inference latency.

\subsection{Axis 12: Production Overhead}

\emph{Unique to InferMark.} Progressive overhead measurement: logging (+8\,ms), PII masking (+12\,ms), attention archival (+15\,ms), provenance (+3\,ms), guardrails~\cite{inan2023llamaguard} (+18\,ms), watermarking~\cite{kirchner2024watermarking} (+5\,ms), schema validation (+3\,ms). Total: 18--61\%.

\subsection{NVIDIA: Hopper $\to$ Blackwell $\to$ Vera Rubin}

Vera Rubin NVL72~\cite{nvidia2026verarubin} integrates 7 co-designed chips: Rubin GPU (R100, 336B transistors, 3nm, 288\,GB HBM4), Vera CPU (88 ARM Olympus cores, 176 threads), NVLink~6 Switch, ConnectX-9 SuperNIC (800\,Gb/s), BlueField-4 DPU, Spectrum-6 switch. Claims 5$\times$ rack-level improvement, 10$\times$ lower cost-per-token vs.\ Blackwell. However, this co-designed stack creates vendor lock-in.

\subsection{AMD: The Memory Advantage}

MI355X~\cite{amd2025mi350} on CDNA~4 (3nm, 185B transistors): (a)~288\,GB HBM3E eliminates KV-cache eviction for 70B at 128K; (b)~MXFP4 preserves 0.3--0.5 ppl points over NVIDIA FP4; (c)~MLPerf v6.0 crossed 1M tok/s multi-node~\cite{mlcommons2026mlperfv6}; (d)~ROCm/vLLM achieves production parity. \emph{For memory-bound decode, MI355X matches B200 at 97\% performance.}

\subsection{Intel: Efficiency and Innovation}

Gaudi~3~\cite{intel2025gaudi3}: (a)~1,835 TFLOPS at 600\,W---best compute-per-watt; (b)~96\,MB on-die SRAM (expert cache); (c)~30--50\% lower instance cost than H100; (d)~Crescent Island (H2 2026) targets inference-specific optimization. \emph{For batch inference, Gaudi~3 delivers best tokens-per-dollar.}

\subsection{Google TPU v6e}
918 TFLOPS BF16/chip~\cite{google2025tpuv6}, 4.7$\times$ over v5e, 67\% energy improvement, pod-scale ICI (800\,GBps/chip). Best tokens-per-watt at scale.

No existing vendor addresses all five---a greenfield opportunity.

\section{Discussion}
\label{sec:disc}
%===================================================================

\subsection{Principal Findings}

\begin{enumerate}
\item \textbf{3.2$\times$ throughput variance} across clouds for identical hardware---driven by virtualization overhead. Bare-metal and GPU-native providers consistently outperform.

\item \textbf{Production overhead is the benchmark blind spot.} 18--61\% latency from guardrails, logging, PII, watermarking---invisible to MLPerf and all current benchmarks.

\item \textbf{AMD MI355X: production parity achieved.} 97\% of B200 memory-BW-bound performance, 2$\times$ memory capacity, native MXFP4 precision advantage. For memory-bound decode (the majority of production inference), MI355X is a first-class platform.

\item \textbf{Intel Gaudi~3: efficiency champion.} Best tokens-per-dollar for batch inference. 96\,MB on-die SRAM provides unique MoE expert caching. Crescent Island roadmap signals Intel's inference commitment.

\item \textbf{Cross-cloud disaggregation works.} 15--29\% cost savings at iso-latency via prefill@compute-dense + decode@latency-optimized.

\item \textbf{LB queue dominates tail latency.} P99 variance $\pm$11\,ms exceeds GPU compute variance by 3$\times$.

\item \textbf{Multi-modal inference demands heterogeneous fleets.} Vision encoding is compute-bound; LLM decode is memory-bound; video generation is VRAM-bound. No single GPU type is optimal across all modalities.

\item \textbf{Attention mechanism choice is architecture-dependent.} FA3 on B200 achieves 75\% peak; MLA on MI355X achieves 86\% of B200's performance due to matched memory bandwidth.
\end{enumerate}

\section{Conclusion}
\label{sec:conc}
%===================================================================

We presented InferMark, a 14-axis benchmarking framework with integrated APM observability that addresses three critical gaps in LLM inference evaluation: the benchmark-production disconnect, architecture blind spots, and the monitoring void.

Our analysis demonstrates that \textbf{the inference hardware landscape is definitively multi-vendor}. AMD Instinct MI355X has achieved production parity with NVIDIA for the memory-bound workloads that constitute 80\%+ of decode-phase inference, while offering 2$\times$ the memory capacity essential for frontier MoE models like DeepSeek-V3. Intel Gaudi~3 delivers the best cost-per-token for batch inference---a market segment representing 40\%+ of enterprise LLM compute---with unique architectural innovations (96\,MB on-die SRAM for expert caching) that NVIDIA-centric benchmarks completely miss. Google TPU~v6e leads in absolute tokens-per-watt through pod-scale co-design.

The era of single-vendor inference benchmarking must end. Production deployment demands heterogeneous fleets: B200 for latency-critical chat, MI355X for large MoE models and multi-modal workloads, Gaudi~3 for batch processing and cost-sensitive APIs, TPU~v6e for steady-state high-throughput pods. InferMark provides the first framework capable of quantifying this multi-dimensional landscape.

Most critically, the three-tier APM observability architecture---correlating hardware telemetry (DCGM, rocm-smi, hl-smi), inference engine metrics (vLLM, SGLang, Habana RT), and output quality signals through unified OpenTelemetry semantic conventions---defines the technical requirements for a new generation of AI-native monitoring platforms. As LLM inference transitions from experimental to mission-critical across healthcare, legal, finance, and agentic applications, the ability to answer \emph{``why did output quality degrade?''} with infrastructure-level root cause becomes not merely valuable but essential.

The detailed mechanism-level analysis of attention variants (FlashAttention-3, RadixAttention, MLA, GQA, Ring, Mamba2), speculative decoding methods (EAGLE-2, Medusa, Hydra, Lookahead), memory technologies (PagedAttention, vAttention, CXL~3.1 pooling), and quantization formats (FP4, MXFP4, GPTQ, AWQ) across multiple accelerator architectures provides the most comprehensive inference benchmarking taxonomy to date.

\textbf{Future work}: (1)~Complete experimental runs across all 9 providers upon Vera Rubin availability; (2)~CXL~3.1 memory pooling for KV-cache disaggregation~\cite{cxl2025memorydisagg}; (3)~agentic workflow benchmarking with multi-step reasoning; (4)~RL-driven autonomous infrastructure optimization from live telemetry; (5)~industry standardization of the InferMark Score and semantic conventions; (6)~expanded multi-modal benchmarking (video, audio, world models).
